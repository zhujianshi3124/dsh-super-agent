A ticket is delivered when the work is done and the report proves it: what was done, the evidence, the checks actually run, and the risks (N-09).
With completion criteria, the report answers each one in the same order with the evidence that shows it holds — a command's output, a diff hunk, a file path; a criterion that could not be verified is reported as unverified, never skipped (N-08). Without criteria, the result alone judges the ticket (C-13a).
Every path changed outside the working directory is listed in the report (C-13d). Every deletion inside the project is recorded: what, where, why and when (C-17).
A vendor key never appears in a report, a log, a message or a command line (C-27).
The report is stored word for word in the ticket and stays readable afterwards, with the whole path from the person's words to the delivery (C-29, C-20).
Ready means verified work, not an unfinished draft; an incomplete result that needs the person is a blocked report with a concrete question, and one that cannot be done is failed (N-13).
A delivered ticket is ended; a later change is a new instruction and a new ticket, never the old one opened again (C-11).
